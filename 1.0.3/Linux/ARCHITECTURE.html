Netory 1.0.3 — Linux architecture

Netory is a self-hosted web application. Users open it in a browser; one application service provides both the web interface and API, with a local SQLite database. A separate database server is not required.

Small architecture diagram

Browser: Netory web interface
        |
        | HTTP :8000 (default)
        v
[Optional HTTPS reverse proxy, e.g. Nginx]
        |  (or connect directly to Netory)
        v
Netory application — Uvicorn + FastAPI
  - Serves the web interface and API
  - Authentication, inventory, discovery, licensing
        |
        +---- SQLite database (db/netory.db)
        +---- Configuration and encryption keys (.env)
        +---- License identity/state (licensing/)
        +---- Application logs (logs/)
        |
        +---- HTTPS to lic.netory.app (online licensing)
        +---- Managed network devices (discovery/probes)

systemd: netory.service
        | starts and supervises
        v
Private Python runtime + Netory application

The proxy is optional. A direct connection goes from the browser to Uvicorn; a proxy connection goes through the proxy before reaching Uvicorn.

Main components

  • Browser interface: displays inventory and settings and sends API requests to the server.
  • Uvicorn + FastAPI: handles web requests, authentication and application features using the bundled private Python runtime.
  • SQLite: stores accounts, inventory and application records in a local database file. Database migrations run during setup/update.
  • Service manager: starts Netory automatically at boot and restarts it after an unexpected failure. The application runs as the restricted netory Linux account.
  • Licensing: preserves the installation identity locally and contacts https://lic.netory.app. A valid license and online licensing access are required for write access.
  • Network discovery: the server probes managed devices; results depend on network reachability and firewall rules. The Linux installer installs Nmap and ping utilities.

Ports and HTTPS

The default address is http://SERVER-IP:8000/; Netory binds to 0.0.0.0. The installer does not install Nginx or change firewall rules. Nginx is optional: it can provide HTTPS and forward requests to Netory. For a proxy on the same machine, install with --bind 127.0.0.1. A different port can be selected with --port.

Files and backups

  • Program and private runtime: /opt/netory/current.
  • Data: /var/lib/netory, including db/netory.db, .env, licensing/ and logs/.
  • Installer update backups: /opt/netory/backups/.

Back up the database together with .env and the licensing directory. Encryption keys are needed to read stored encrypted credentials. Program files are separate from customer data; protected application/runtime files are verified at startup and should not be edited.

Quick service check

sudo systemctl status netory --no-pager
sudo journalctl -u netory -n 50 --no-pager
curl -I http://127.0.0.1:8000/

Use your configured port if it differs from 8000. The curl command checks the default direct HTTP configuration on the server itself.
